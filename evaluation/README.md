# SpringMind 评测总览

截至 2026-10-11。本页汇总已有实验的主要结论、指标口径和报告入口，不替换原始结果，也不改变应用默认配置。

## 1. 先记住三个结论

| 要回答的问题 | 主要证据 | 可以得出的结论 |
| --- | --- | --- |
| 双路融合有没有价值？ | NFCorpus：BM25 的 nDCG@10 为 0.3222，RRF 为 0.3458 | 在这套公开检索集上，相对较强单路提升约 **7.3%**；不代表所有数据集都获益 |
| 精排有没有改善证据选择？ | MultiHop：向量链路最终上下文事实召回率 39.58% → 54.73% | Qwen 精排带来 **15.15 个百分点**的提升；这是向量链路的收益，不是双路融合的收益 |
| 最终回答有没有变好？ | MultiHop 裁定后：向量基线 26/49，向量＋精排与双路＋精排均为 28/49 | 调整后问答准确率 53.06% → 57.14%，增加 **4.08 个百分点**；两种精排链路打平 |

三行分别衡量**排序质量、证据覆盖、回答正确性**，不能拼成同一套数据上的连续提升，也不能将其中一个指标称为另一个指标。

## 2. 为什么测了这么多？

实验顺序对应问题逐步细化，不是不断换题直到双路获胜：

1. **先打通链路**：Northstar 验证真实入库、检索、精排及结果采集，但资料很少，容易接近满分。
2. **排查意外结果**：Harborview 中关键词单路更好，于是分别控制文件名、向量模型、融合策略，避免把所有差异都归因于 RRF。
3. **增加挑战并冻结题目**：Meridian 引入相似标识符、时间和适用范围、多证据问题；仍保留强向量优于融合的结果。
4. **引入外部检索基准**：BEIR 使用公开固定题目和相关性标注，降低自建题目的偏差；它衡量检索，不衡量生成答案。
5. **验证证据到答案的传递**：MultiHop-RAG 有标准答案和证据，固定同一批题目，依次测召回、精排、生成，定位收益与损失发生在哪一层。

候选并集用于回答「两路是否找到不同证据」，RRF 用于回答「融合排序是否把证据排到前面」。有互补候选不等于最终上下文更完整，更不等于答案一定正确。

## 4. 主要结果怎么读？

### 4.1 公开检索：双路有收益，但不是必胜

BEIR 使用受控的英文 BM25 与本地 BGE-M3 精确向量检索，相同 title＋body 输入。RRF 常数为 60，输入深度 50 / 1000 在测量前固定。

| 官方测试集 | BM25 | BGE-M3 | RRF，深度 50 | RRF，深度 1000 |
| --- | ---: | ---: | ---: | ---: |
| SciFact，300 题，nDCG@10 | 0.6826 | 0.6436 | 0.7011 | 0.6998 |
| NFCorpus，323 题，nDCG@10 | 0.3222 | 0.3152 | 0.3458 | 0.3492 |

- NFCorpus 的 RRF50 相对较强单路 BM25 提升约 7.3%；绝对增量 0.0236，配对 bootstrap 95% 区间为 [0.0120, 0.0355]。
- SciFact 的均值也更高，但增量区间为 [-0.0037, 0.0405]，包含 0，不能声称对较强单路有明确统计优势。
- 这是英文受控基准，不是项目 IK 分词、文件名加权链路的原样线上测量，也不能据此宣称中文、跨语言或真实用户查询同样提升。

### 4.2 精排：平均证据覆盖改善，不保证所有事实都保住

MultiHop 正式集的 44 道可回答题；最终上下文统一限制为最多 5 个窗口、4096 token。指标为各题参考事实召回率的宏平均。

| 检索链路 | 精排前 | Qwen 精排后 | 增量 | 全部参考事实齐全的题数 |
| --- | ---: | ---: | ---: | ---: |
| 关键词 | 43.18% | 48.48% | +5.30 个百分点 | 10/44 → 9/44 |
| BGE-M3 向量 | 39.58% | 54.73% | +15.15 个百分点 | 6/44 → 10/44 |
| RRF | 47.54% | 51.52% | +3.98 个百分点 | 11/44 → 10/44 |

平均覆盖提高与完整覆盖题数下降可以同时发生：多道题各多找到一条事实，并不抵消另一些题从完整变为缺一条事实。向量＋精排在本次平均覆盖指标上最好，不能只展示双路＋精排。

使用 `qwen3-rerank`，180 次请求全部应用成功。评测超时为 10 秒，不是应用默认的 2 秒；本轮成功率不能当作默认超时下的保证。

### 4.3 回答：以裁定后版本为当前入口，原始版本不覆盖

生成模型为配置的 `deepseek-flash`。先执行 10 题 × 4 组校准，再执行 50 题 × 4 组正式评测；复用已有上下文，没有重新检索或精排。

| 对照组 | 原始严格匹配，50 题 | 裁定后，49 题 | 裁定后仅可回答题，43 题 |
| --- | ---: | ---: | ---: |
| 向量 | 23/50 = 46% | 26/49 = 53.06% | 20/43 = 46.51% |
| RRF | 25/50 = 50% | 26/49 = 53.06% | 20/43 = 46.51% |
| 向量＋Qwen | 26/50 = 52% | 28/49 = 57.14% | 22/43 = 51.16% |
| RRF＋Qwen | 26/50 = 52% | 28/49 = 57.14% | 22/43 = 51.16% |

当前口径为**调整后问答准确率 / 得分（自动判分＋5 题用户批准的争议裁定）**，不是全量人工验证的语义准确率或忠实度。四组均正确拒答 6/6 道无答案题，样本太少，不据此宣称普遍的 100% 拒答可靠性。

裁定统一应用于各组：m1594 修正参考实体、m0735 接受 Yes / True 等义、m1727 保留错误判定、m1748 按明确答案命题判定、m2398 因语义歧义从四组共同排除。仅这五题的裁定已确认，不能把未标记或未裁定的回答视为人工通过。

绝对得分因评分修正而提高，不代表模型重新优化。最新对照只支持精排组多答对 2 题；双路本身及两种精排链路分别打平，不能将 +4.08 个百分点全部归功于 RRF。保留歧义题时增量为 4.00 个百分点，另排除答案泄漏题时为 4.17 个百分点，详见裁定报告的敏感性检查。

## 5. 指标口径速查

| 指标 / 术语 | 本项目中如何理解 | 不能混淆的内容 |
| --- | --- | --- |
| Hit@k | 前 k 条中是否至少命中一条标注相关结果，再对题目平均 | 有一条相关证据不等于证据完整 |
| Recall@k | 前 k 条命中的标注相关结果数 / 该题全部标注相关结果数，再按报告约定平均 | 文档、切片、事实是不同统计单位；不能直接跨报告比较 |
| MRR@k | 首条相关结果排名的倒数，前 k 条无命中则为 0 | 不衡量多条证据是否齐全 |
| nDCG@k | 相关结果是否排在前面，按相关性等级、位置折扣及理想排序归一化 | 是排序质量，不是回答准确率；BEIR 用线性 gain，自建分级工具用 `2^grade - 1` |
| 最终上下文事实召回率 | 每题被选入上下文的完整官方参考事实数 / 该题参考事实总数，再对可回答题宏平均 | 不是候选池 Recall@k，也不是回答正确率；替代性充分证据可能不在官方参考中 |
| All facts / 完整覆盖 | 覆盖该题全部参考事实的题数 / 对应可回答题数 | 比平均事实召回更严格，也不等于逻辑上答题所需的最小证据 |
| U25 / U50 候选并集 | 每路取前 25 / 50 条去重，最多 50 / 100 条；本身无排序 | U50 对比单路 top50 有容量差异，不能当成同预算胜利 |
| 调整后问答准确率 | 按保留的自动评分和显式裁定，正确回答数 / 纳入评分的题数；49 题版本包括正确拒答 | 不是所有解释都正确、引用都充分或全量人工核验 |
| 引用有效性 / 支持代理指标 | 分别检查引用文字位置，或严格参考事实覆盖等条件 | 引用原文存在不等于支持答案；代理指标不等于语义忠实度 |

自建分级中，3 表示单条证据足以回答，2 表示直接支持部分答案，1 表示背景，0 表示不相关；原工具的 Hit/Recall/MRR 按 `grade > 0` 计算，包含背景级，不应改述为「直接答案证据召回率」。各实验以其冻结协议为准。

**分母不要混用：**

- 60：全部 MultiHop 题目 = 10 校准＋50 正式；校准不并入正式得分。
- 44：原正式集可回答题，用于已发布的召回和精排指标；6 道无答案题不参与这些召回均值。
- 49：答案裁定后正式集，排除 1 道歧义题，仍包含 6 道无答案题。
- 43：裁定后正式集仅可回答题。
- 后续答案裁定没有回写旧召回与精排报告，44 题结果仍属于原参考版本。

**增量不要混用：**39.58% → 54.73% 是增加 15.15 个百分点；0.3222 → 0.3458 是绝对增加 0.0236、相对增加约 7.3%。增量按未舍入原值计算，展示值相减可能存在末位舍入差异。

## 7. 保留原则与后续边界

- **主结论**：BEIR 检索、MultiHop 精排、MultiHop 裁定后回答。自建小规模集的接近满分结果不作为普遍质量的证明。
- **辅助证据**：Harborview 字段与模型消融、Meridian 暂定挑战结果、Northstar 回归资料；不因不支持双路优势而删除。
- **原始与裁定版本并存**：保留冻结题目、标注、配置、采集记录、原始评分和新裁定；修正评分不是重新调用模型，也不是覆盖历史。
- **复用与控制变量**：交叉对照复用既有排名，精排固定候选，生成固定上下文，减少重复费用并隔离阶段影响。候选上限、窗口数和 token 预算必须随结论一起解释。
- **保持适用范围**：公开题目可能存在模型训练重叠；小样本、英文资料、评测提示词不代表真实用户分布或线上质量。BGE-M3 精确检索是评测配置，未改应用默认模型。
- **不混用耗时**：生成耗时不包含缓存的检索和精排；不能把各阶段 p95 直接相加宣称在线端到端 p95。
- **后续实验**：不以提高得分为目的更换测试题。未来若调整分块、融合权重或窗口策略，先用开发 / 校准数据，再冻结新的确认集；当前已反复分析的正式集不能继续称为未触碰的留出集。

重现细节见 [BEIR 协议](retrieval/beir/README.md)、[MultiHop 检索协议](retrieval/multihop/README.md)、[精排协议](rerank/multihop/README.md)、[生成协议](answer/multihop/README.md)。阅读本页和已有报告不需要任何模型调用；若执行重现命令，先区分离线验证与显式付费采集，Java 工具使用 Java 21。
